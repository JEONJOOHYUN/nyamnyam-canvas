# FIRMWARE_NOTES — 부품 코드 작성 시 참고사항

> 웹에서 기기와 관련된 부분(타입, API, 명령, 필터 기준, 상태 머신)을 바꾸면 이 파일도 같이 고친다.
> 아직 부품이 도착하지 않았고 펌웨어 코드도 없다. 7단계에서 완성한다. 여기 적힌 값은 `docs/SPEC.md` 기준 초안이다.

## 1. 하드웨어 사양과 배선

| 부품          | 모델                                                  | 비고                                                                          |
| ------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------- |
| 보드          | ESP32 DevKitC V4 (ESP32-WROOM-32E), USB-C             | Wi-Fi 2.4GHz만 지원                                                           |
| 무게센서      | (주)우정하이텍 로드셀 5kg, 4선식 Full Bridge, Al Beam | 선 색은 제품 SPEC표 확인 필요 (일반적으로 빨강 E+, 검정 E−, 초록 A+, 하양 A−) |
| 앰프          | 키트128 WAT-HX711 (핀 납땜됨), 2.6~5.5V               | 핀 순서 VCC·SCK·DT·GND (인쇄된 글자 기준)                                     |
| 전원          | 보조배터리 또는 5V 충전기 (USB-C)                     | 시연용                                                                        |
| 물리 버튼·LED | 없음                                                  | 영점은 화면 버튼으로                                                          |

| HX711 | ESP32             |
| ----- | ----------------- |
| VCC   | **3V3** (5V 금지) |
| GND   | GND               |
| DT    | **GPIO16**        |
| SCK   | **GPIO4**         |

## 2. 데이터 계약 — `WeightReading`

웹 `lib/weight/types.ts`(2단계에서 작성)와 이름·단위·의미가 완전히 같아야 한다.

```json
{ "grams": 312.4, "raw": 314.1, "stable": true, "seq": 1024, "ts": 5234123 }
```

| 필드   | 타입    | 단위 | 의미                                   |
| ------ | ------- | ---- | -------------------------------------- |
| grams  | number  | g    | 필터 적용, 영점 기준 순 무게           |
| raw    | number  | g    | 필터 전 값을 g로 환산 (디버그용)       |
| stable | boolean | —    | 최근 1초 변동폭이 임계값 이하          |
| seq    | number  | —    | 증가하는 일련번호. 뒤로 가면 웹이 무시 |
| ts     | number  | ms   | ESP32 `millis()` 또는 epoch ms         |

## 3. Edge Function API

7단계에서 작성. 계약 초안: `/functions/v1/device-ingest`(상태 전송), `/functions/v1/device-commands`(명령 polling). `device_id + device_key`로 인증하고 anon key는 쓰지 않는다.

## 4. 명령 목록

`tare`, `calibrate`(payload: 기준 무게 g), `reboot`. 처리 순서와 결과 보고 형식은 7단계에서 정한다.

## 5. 필터와 안정 판단 기준값 (웹·펌웨어 공유)

| 항목            | 값                                                |
| --------------- | ------------------------------------------------- |
| HX711 읽기 주기 | 10~80Hz                                           |
| 필터            | 중앙값(최근 5개) → 이동평균                       |
| 안정 판단       | 최근 1초 변동폭 ±3g 이하                          |
| 보정값 저장     | NVS(Preferences): calibration factor, tare offset |

## 6. 전송 주기와 타임아웃

- 값이 ±1g 이상 변했거나 1초가 지났을 때만 전송, 최대 약 4Hz
- 명령 polling 1초
- 웹은 3초 이상 업데이트가 없으면 `offline`

## 7. 테스트 절차

시리얼(115200) 확인 → 보정(`t`, `c 510`) → 웹 연결 확인. 7단계에서 자세히 적는다.

## 8. 자주 하는 실수

- HX711을 5V에 연결
- 5GHz Wi-Fi에 연결 시도
- 충전 전용 USB 케이블 사용
- 로드셀 화살표 방향 반대
- 상판이 케이스에 닿음
- 로드셀 흰 부분(게이지) 누름

# 냠냠캔버스 (nyamnyam-canvas) — 웹사이트 개발 프롬프트

> 2026-10-14 사용자가 준 원본 요구사항 그대로. 결정이 바뀌면 이 파일이 아니라 `HANDOFF.md`의 "주요 설계 결정"에 기록한다.

## 0. 너의 역할과 프로젝트 요약

너는 이 프로젝트의 리드 개발자야. 아래 요구사항으로 **"냠냠캔버스"** 웹앱을 만든다.

- **무엇**: 아이가 밥을 먹으면, 식판 아래 무게센서(로드셀)가 줄어든 무게를 재고, 그만큼 화면 속 그림이 자라나는 식습관 보조 앱. 캐릭터가 움직이며 말로 응원한다.
- **누가 쓰나**: 아이(4~8세)가 식탁에서 태블릿이나 휴대폰으로 보는 **아이 화면**, 부모가 세팅하는 **부모 설정 페이지**.
- **현재 상황**: 하드웨어(ESP32, 로드셀, HX711)가 아직 도착하지 않았다. 그래서 **웹사이트를 먼저 만들고, 무게는 시뮬레이터로 대신한다.** 단, 나중에 부품이 오면 **코드 한 군데(데이터 소스)만 바꿔 바로 연결되도록** 설계한다.
- **개발자**: 전주현 혼자 웹, 펌웨어, 하드웨어를 모두 맡는다. 캡스톤디자인 2 과제다(팀장 전주현, 팀원 이다빈). 발표 시연이 목표지만 품질은 실제 제품처럼 만든다.
- **GitHub 저장소**: https://github.com/JEONJOOHYUN/nyamnyam-canvas.git
  - 웹앱, 펌웨어, 문서를 모두 이 저장소 하나에서 관리한다 (모노레포). Git 규칙은 14장을 따른다.

| ------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------- |

## 1. 기술 스택 (내가 쓰는 도구, 필요한 것만 알맞게 사용)

- **Next.js (App Router, TypeScript) + React** — 메인 프레임워크
- **Tailwind CSS + shadcn/ui** — 부모 설정 페이지 UI는 shadcn/ui로, 아이 화면은 Tailwind와 직접 만든 일러스트로
- **Supabase** — 부모 로그인(Auth), 설정과 식사 기록 저장(Postgres + RLS), **기기↔웹 실시간 연결(Realtime)**
- **Vercel** — 배포. GitHub 저장소와 연결해서 `main`은 실제(Production) 주소로, `dev`는 미리보기(Preview) 주소로 자동 배포되게 한다.
- **애니메이션**: `motion`(Framer Motion) + SVG를 기본으로 사용. 이유를 HANDOFF.md에 기록할 것.
  - 실시간으로 무게에 반응해야 하므로 **코드로 제어하는 SVG + Motion**이 맞다.
  - Lottie나 Rive는 디자인 툴로 만든 파일이 필요해서 지금은 쓰지 않는다. 나중에 디자이너 파일이 생기면 교체할 수 있게, 캐릭터는 컴포넌트 단위로 분리한다.
  - HyperFrames 같은 HTML→영상 렌더링 도구는 **실시간 앱 화면에는 쓰지 않는다.** 발표용 홍보 영상을 만들 때만 선택적으로 검토한다.
- **효과음**: Web Audio API로 직접 합성(저작권 문제 없음)하는 것을 기본으로 한다. 파일을 쓸 경우 CC0 라이선스 음원만 쓰고 출처를 `docs/ASSETS.md`에 적는다.
- **음성**: 캐릭터 대사는 **네이버 클로바더빙으로 미리 만든 mp3를 재생**한다 (실시간 유료 API 호출 없음).
  - 제작 방법은 **13장**을 따른다.
  - 파일 경로 규칙은 `public/voices/<character>/<lineId>.mp3`이다.
  - 파일이 없는 대사만 브라우저 TTS(Web Speech API, ko-KR)로 대신 읽는다.
  - 입 움직임은 오디오 재생 시작과 끝, Web Audio 음량 분석으로 동기화한다.
- **상태관리**: React 상태 + Zustand(필요할 때만). 과하게 늘리지 말 것.
- **PWA**: 홈 화면 추가, 식사 중 화면 꺼짐 방지(Screen Wake Lock API), 전체화면 버튼.

## 2. ⚠️ 가장 중요한 설계 결정: 기기 연결 구조

**문제**: Vercel 사이트는 HTTPS다. 반면 집 안 ESP32는 `http://192.168.x.x` 같은 로컬 주소다. 브라우저는 HTTPS 페이지에서 로컬 HTTP나 WS로 접속하는 것을 **혼합 콘텐츠로 차단**한다. 그래서 웹이 ESP32에 직접 접속하는 방식은 배포 환경에서 작동하지 않는다.

**해결**: 웹과 ESP32가 직접 대화하지 않고 **Supabase를 가운데 두고** 주고받는다.

```
[로드셀]→[HX711]→[ESP32] --HTTPS(REST)--> [Supabase: device_state 테이블 upsert]
                                                  │ Realtime(postgres_changes)
                                                  ▼
                                   [웹 아이 화면 (Vercel, HTTPS)]
[웹 부모 설정] --insert--> [Supabase: device_commands] <--1초마다 polling-- [ESP32]
```

**`WeightSource` 추상화를 반드시 만든다.** 아이 화면은 이 인터페이스만 알고, 소스가 무엇인지는 모른다.

```ts
// lib/weight/types.ts
export type WeightReading = {
  grams: number; // 필터가 적용된 순 무게 (영점 기준, 영점을 잡은 뒤 올린 무게만 포함)
  raw: number; // 필터 전 HX711 값을 g로 환산한 값 (디버그용)
  stable: boolean; // 기기가 판단한 안정 상태
  seq: number; // 증가하는 일련번호 (순서 꼬임과 중복 방지)
  ts: number; // ESP32 millis() 또는 epoch ms
};
export interface WeightSource {
  connect(): Promise<void>;
  disconnect(): void;
  subscribe(cb: (r: WeightReading) => void): () => void;
  sendCommand(cmd: DeviceCommand): Promise<void>; // tare, calibrate 등
  status: "idle" | "connecting" | "online" | "offline" | "error";
}
```

구현체는 세 개를 만든다.

1. **`SimulatorSource`** (지금 기본값): 슬라이더, "한 입 먹기", "숟가락으로 꾹 누르기(순간 튐)", "식판 들어올리기(0g)", "센서 노이즈 ±2g" 버튼으로 실제 센서 동작을 흉내 낸다. 개발 모드와 부모 설정의 "시연 모드"에서 사용한다.
2. **`SupabaseRealtimeSource`** (배포용): `device_state`의 Realtime 업데이트를 구독한다. `seq`가 뒤로 가면 무시하고, 3초 이상 업데이트가 없으면 `offline`으로 표시한다.
3. **`LocalWebSocketSource`** (선택, 인터넷 없는 시연장 대비): ESP32가 `ws://<ip>:81`로 같은 JSON을 보낸다. **`http://localhost`에서 실행할 때만** 쓸 수 있다는 점을 UI와 문서에 명시한다.

**환경변수와 설정에서 소스를 고를 수 있게** 한다 (`NEXT_PUBLIC_WEIGHT_SOURCE=simulator|supabase|localws`, 부모 설정에서도 전환 가능).

## 3. 무게 측정 정확도 (초기부터 최우선)

정확도는 **기기(펌웨어)와 웹, 두 단계에서 책임을 나눈다.** 이 분담을 그대로 지킬 것.

**ESP32 쪽 (펌웨어가 할 일)**

- HX711을 10~80Hz로 읽는다.
- **중앙값 필터(최근 5개) → 이동평균**으로 노이즈를 줄인다.
- 최근 1초 동안의 변동폭이 임계값(예: ±3g) 이하일 때만 `stable=true`로 보낸다.
- 보정계수(calibration factor)와 영점(offset)은 **ESP32 NVS(Preferences)에 저장**해서, 재부팅해도 유지되게 한다.
- 값이 변했거나(±1g 이상) 1초가 지났을 때만 전송해서 트래픽을 아낀다. 최대 전송 주기는 약 4Hz다.

**웹 쪽 (식사 로직이 할 일)**: 다음 상태 머신으로 처리한다.

- 상태: `EMPTY_TRAY → SERVED(시작 무게 확정) → EATING → ENDED`
- **시작 무게**: `stable` 상태로 3초 이상 유지된 값만 확정한다.
- **진행률**: (시작 무게 − 현재 안정 무게) ÷ 음식 무게
  - **안정값만 반영**한다.
  - **진행률은 절대 줄어들지 않는다** (최대값 유지).
- **순간 튐 무시**: 숟가락으로 누르기 같은 순간적인 무게 증가는 무시한다.
- **식판 들어올림**: 무게가 0 근처로 떨어지면 일시정지하고, 다시 올라오면 이어서 진행한다.
- **추가 배식**: 시작 무게보다 일정량(예: 30g) 이상 늘고 안정되면, 부모 설정에 따라 둘 중 하나로 처리한다.
  - "추가 배식으로 인정": 음식 무게를 늘린다.
  - "무시"
- **비정상 감지**: 음식 무게가 아주 빨리 줄면(예: 2초에 50% 이상) **음식을 버린 것으로 의심**해서 진행 반영을 보류한다. 참고 사례: 미국 특허 US9672755B2의 섭취 속도 판단 방식.

**부모 설정의 "센서 보정 마법사"**

1. 식판을 비우고 → [영점 잡기]
2. 무게를 아는 물건(예: 500ml 생수 = 약 510g)을 올리고 → 무게 입력 → [보정]
3. 다시 올려서 오차가 ±5g 이내인지 확인 → 통과 표시
4. 오차가 크면 원인 안내: 로드셀이 상판에 닿음, 화살표 방향 반대, 선 연결 등

**시뮬레이터에도 노이즈와 튐을 넣어서**, 필터와 상태 머신을 부품 없이 테스트할 수 있게 한다. 이 로직은 순수 함수로 만들고 **Vitest 단위 테스트**를 작성한다.

## 4. 화면 구성

### 4-1. 아이 화면 (`/play`)

- **테마 선택**: 처음에 또는 부모가 허용하면 아이가 직접 고른다.
  - **캐릭터** (목소리 포함, 최소 3종). 모두 **오리지널 캐릭터**로 만들고, 기존 유명 캐릭터와 닮게 만들지 않는다.
    - 냠냠이(병아리): 클로바더빙 **다인**(아동 여). 밝고 귀여운 메인 캐릭터
    - 퐁당이(아기 해달): 클로바더빙 **하준**(아동 남). 해맑은 장난꾸러기 (2026-10-15 포동이(곰)에서 변경, `docs/CHARACTERS.md`)
    - 반짝이(누나 별): 클로바더빙 **아라**(어른 여). 다정하게 칭찬해 주는 누나
    - 각 캐릭터마다 성격과 말투(대사 문체)를 다르게 한다. 음성 옵션 값은 13장 표를 따른다.
  - **맵** (최소 3종). 각각 **7단계로 자란다.**
    - 숲: 씨앗 → 새싹 → 작은 나무 → 큰 나무 → 꽃 → 열매 → 새와 무지개
    - 바다: 빈 바다 → 물방울 → 해초 → 산호 → 작은 물고기 → 거북이 → 고래 분수
    - 우주: 밤하늘 → 별 → 행성 → 로켓 부품 → 로켓 조립 → 우주인 → 발사
- **자라나는 그림**
  - **둥글둥글하고 아이들이 좋아할 그림이되, 퀄리티는 있어야 한다.**
    - 부드러운 그라데이션, 은은한 그림자와 하이라이트를 쓴다.
    - 맵마다 일관된 5~7색 팔레트를 정한다.
    - 선 두께와 모서리 둥글기를 통일한다.
  - 단계별 그림은 SVG 레이어 컴포넌트로 만든다 (`components/maps/forest/Stage3.tsx` 등).
- **단계별 애니메이션**: Motion 사용.
  - 새 단계가 나타날 때: 스프링으로 커지며 등장하고, 반짝이 파티클이 나온다.
  - 평소: 잎이 살랑이고 구름이 흐르는 정도의 은은한 움직임을 준다.
  - 완성: 축하 연출(컨페티, 캐릭터 춤)을 3~4초 보여준다.
  - `prefers-reduced-motion`을 존중한다.
- **캐릭터 움직임**
  - 평소: 숨쉬기, 눈 깜빡임
  - 말할 때: 입 움직임(음성 재생과 동기화), 몸짓
  - 단계가 오를 때: 점프
  - 캐릭터를 터치하면 반응한다.
- **말풍선과 대사**
  - 단계별 응원 대사를 준비한다.
  - 일정 시간(부모 설정, 기본 30초) 변화가 없으면 **부드럽게 기다리는 말**을 한다.
  - **혼내거나 재촉하는 말, 몸매나 체중과 연결된 말은 절대 금지**다. 대사 목록은 `content/lines.ts`에 모아 두어 부모가 검토할 수 있게 한다.
- **"배불러요" 버튼** (부모가 켜고 끌 수 있음)
  - 누르면 칭찬하며 마무리한다. 그림은 줄어들지 않는다.
  - 부모가 정한 기준(예: 70%) 이상이면 오늘 도장을 준다.
- **진행 표시**: 단계 점과 진행 막대. 숫자 %는 부모 설정으로 숨길 수 있다.
- **기기 상태 표시**: 연결됨 / 끊김 / 시뮬레이터. 끊김일 때는 아이에게 불안하지 않게 작게 표시한다.
- **주간 도장판과 "내 그림 앨범"**: 완성한 그림을 모아서 본다.

### 4-2. 부모 설정 페이지 (`/parent`, shadcn/ui)

- **진입 보호**: Supabase 로그인과 **4자리 PIN**을 둬서, 아이가 실수로 들어가지 못하게 한다.
- **아이 프로필**: 이름, 나이. 여러 명을 지원한다.
- **그림 완성 방식** ⭐
  - (A) **먹은 양 기준**: 한 끼에 그림 1장 완성. 담은 음식 대비 % 진행.
  - (B) **식사 횟수 기준**: N번의 식사로 그림 1장 완성. 예: 7끼 = 1장. 한 끼를 "완료"로 볼 기준 %도 설정한다.
  - (C) **누적 양 기준**: 여러 끼에 걸쳐 총 Xg을 먹으면 완성.
- **단계 기준값**: 기본 10/25/40/55/70/85/95%. 고급 설정에서 조정한다.
- **배불러요 옵션**: 버튼 표시 여부, 도장 인정 기준 %, 버튼을 눌렀을 때 캐릭터 대사
- **대기 시간**: 무반응 몇 초 뒤에 말을 걸지, 말을 거는 최대 횟수(과한 재촉 방지)
- **소리**: 효과음과 음성의 볼륨과 켜기/끄기, 캐릭터 음성 미리듣기, 녹음 파일 업로드(선택, Supabase Storage)
- **테마**: 아이가 직접 선택하게 할지, 부모가 고정할지
- **기기 연결**
  - 기기 등록: 기기 ID와 연결 키를 발급하고, ESP32에 넣을 값을 복사 버튼으로 보여준다.
  - 연결 상태와 실시간 무게를 표시한다.
  - 데이터 소스를 전환한다 (시뮬레이터 / 기기).
- **센서 보정 마법사** (3장 참고)
- **추가 배식 처리 방식**, 비정상 감지 켜기/끄기
- **식사 기록**: 날짜별 먹은 양, 걸린 시간, 완성 여부. 간단한 차트로 보여준다.
- **⚠️ 안내 문구**: "많이 먹이기보다 적정량을 담아 주세요"를 설정 화면에 고정으로 표시한다.

## 8. 펌웨어 (ESP32) — 웹과 동시에 준비

부품이 오기 전에 **펌웨어 코드도 `firmware/nyamnyam/nyamnyam.ino`로 작성**해 둔다. 부품이 도착하면 Wi-Fi 정보와 기기 키만 넣고 바로 연결되게 한다.

- **Arduino IDE 기준**
  - 보드: "ESP32 Dev Module"
  - 라이브러리: `HX711` (Bogdan Necula), `ArduinoJson`, `Preferences`, `WiFiClientSecure`, `HTTPClient`
- **기능**
  - Wi-Fi 연결 (설정은 `secrets.h`로 분리하고 `.gitignore`에 추가. 대신 값을 비워 둔 `secrets.example.h`를 커밋한다)
  - HX711 읽기 → 필터 → 안정 판단 → Edge Function으로 상태 전송
  - 명령 polling(1초) → tare / calibrate 실행 → 결과 보고
  - 보정값을 NVS에 저장
  - 시리얼 모니터(115200) 디버그 출력과 시리얼 명령(`t`=영점, `c 510`=510g으로 보정)
- **선택 기능**: `LOCAL_WS` 플래그를 켜면 포트 81에서 WebSocket으로 같은 JSON을 내보낸다.
- **반드시 지킬 것**: 웹의 `WeightReading` 타입과 펌웨어가 보내는 JSON 필드는 **이름, 단위, 의미가 완전히 같아야 한다.** 한쪽을 바꾸면 반드시 다른 쪽과 문서를 같이 고친다.

## 12. 품질 기준과 금지사항

- TypeScript strict. `any`는 금지.
- 로직(필터, 상태 머신, 진행률 계산)은 UI와 분리된 순수 함수로 만들고 테스트한다.
- **아이에게 하는 말**: 칭찬과 기다림만 쓴다. 비교, 벌, 체중이나 몸매에 대한 언급은 금지다.
- **그림은 절대 줄어들지 않는다.** 한 번 얻은 진행은 유지된다.
- 유명 캐릭터, 브랜드, 저작권 음원과 이미지는 사용하지 않는다.
- 비밀값(Supabase service key, 기기 키, Wi-Fi 비밀번호)은 커밋하지 않는다.
- 한국어 UI. 아이 화면 글씨는 크고 짧게 쓰고, 한글 둥근 서체(예: Google Fonts "Jua")를 쓴다. 부모 화면은 가독성이 좋은 본문 서체를 쓴다.
- 모르는 것은 추측하지 말고 HANDOFF.md의 "알려진 문제"에 적은 뒤 나에게 물어본다.

## 13. 캐릭터 음성 제작 (클로바더빙 + Chrome 자동화)

**언제 하나**: 11장 3단계에서 `content/lines.ts`(대사 목록)가 확정되면 진행한다. 그 전까지는 브라우저 TTS로 개발한다.

### 13-1. 서비스와 제한

- 서비스: **네이버 클로바더빙** (https://clovadubbing.naver.com) 무료 플랜
  - 사용자(전주현)가 **이미 로그인해 둔 Chrome**에서 작업한다.
- **무료 플랜 제한**: 월 15,000자, **다운로드 월 20회**, 출처 표기 필수, 상업적 이용 제한
- **목표**: 캐릭터당 프로젝트 1개, **다운로드는 캐릭터당 1회**, 총 3회 이내로 끝낸다.
- 다운로드하기 전에 남은 횟수를 화면에서 확인하고 사용자에게 알린다.

### 13-2. 화자와 보이스 옵션

클로바더빙의 무료 화자는 아라, 민상, 다인, 하준이다.

| 캐릭터 | 화자           | 성격        | 시작 옵션 (미리듣기 후 사용자와 조정)                    |
| ------ | -------------- | ----------- | -------------------------------------------------------- |
| 냠냠이 | 다인 (아동 여) | 밝고 귀여움 | 특수효과 없음, 속도 −1, 높낮이 보통, 끝음 처리/길이 보통 |
| 퐁당이 | 하준 (아동 남) | 해맑음      | 특수효과 없음, 속도 −1, 높낮이 보통, 끝음 처리/길이 보통 |
| 반짝이 | 아라 (어른 여) | 다정한 누나 | 특수효과 없음, 속도 −1, 높낮이 보통, 끝음 처리/길이 보통 |

- 클로바더빙 화면의 보이스 옵션: 특수효과, 속도(−5~+5), 높낮이, 끝음 처리, 끝음 길이, 볼륨 조절
- 아동 화자는 감정 조절 기능이 없으므로 **문장 부호("!", "~", "?")로 억양을 살린다.**
- 아이가 알아듣기 쉽게 기본 속도보다 조금 느리게 시작한다.
- 확정한 옵션 값과 프로젝트 이름은 `docs/VOICE_SCRIPT.md` 맨 위에 기록해서, 나중에 다시 만들 때 똑같이 재현할 수 있게 한다.

### 13-3. 대본 만들기

- `content/lines.ts`를 바탕으로 `docs/VOICE_SCRIPT.md`를 자동 생성한다.
  - 캐릭터별로 묶는다.
  - 각 줄에 순번, lineId, 문장, 억양 팁을 적는다.
- 한 문장은 짧게(25자 안팎) 쓴다. 아이 이름 같은 변하는 값은 넣지 않는다.

### 13-4. Chrome 자동화 절차

**도구**: Claude Code의 **Chrome 연동**(Claude in Chrome 확장, `claude --chrome` 또는 `/chrome`)으로 사용자의 Chrome을 조작한다. 연동을 쓸 수 없으면 자동화하지 말고, 대본과 붙여넣기용 텍스트만 만든 뒤 사용자에게 수동 진행 방법을 안내한다.

캐릭터마다 다음 순서로 진행한다.

1. 클로바더빙에서 **새 프로젝트**를 만든다. 이름은 `nyamnyam_<character>_v1`로 한다.
2. 화자를 선택하고 13-2의 보이스 옵션을 적용한다.
3. 대본 순서대로 문장마다 **'더빙 추가'**로 한 줄씩 입력한다.
4. **대사 사이 공백을 1.0초 이상**으로 설정한다. 화면의 "0.10초" 공백 버튼이다. 무음 기준으로 자르기 쉽게 하기 위해서다.
5. 앞의 3~4줄을 **미리듣기**하고 사용자에게 확인을 받는다. 필요하면 옵션을 조정한다.
6. **사용자가 승인하면** 다운로드한다.
   - 다운로드 창에 **문장별(개별) 파일 옵션**이 있으면 그걸 쓴다.
   - 없으면 mp3 한 파일로 받는다.
7. 받은 파일을 `voices-src/<character>/`로 옮긴다. 원본이 크면 `.gitignore`에 넣는다.

### 13-5. 자르기와 배치

- `scripts/split-voices.ts`: ffmpeg `silencedetect`로 한 파일을 문장 단위로 자른다.
  - 대본 순서대로 `public/voices/<character>/<lineId>.mp3`로 저장한다.
  - 앞뒤 무음은 다듬고, 음량은 정규화한다.
  - **잘린 개수와 대본 줄 수가 다르면 저장하지 말고 중단**한 뒤, 어디가 어긋났는지 보고한다.
- 개별 파일로 받은 경우에는 이름만 lineId 규칙으로 바꾼다.
- 앱의 개발 모드에 **"음성 점검" 화면**을 만든다. 모든 대사를 목록으로 보여주고 하나씩 재생해서, 누락되거나 순서가 꼬인 파일을 찾을 수 있게 한다.

### 13-6. 안전 규칙 (반드시 지킬 것)

- **로그인과 비밀번호 입력은 사용자가 직접 한다.** 자동화로 계정 정보를 입력하지 않는다.
- **다운로드, 프로젝트 삭제, 결제와 관련된 클릭은 매번 사용자에게 먼저 확인받는다.**
- 사람이 작업하는 속도로 천천히 진행한다. 같은 요청을 짧은 시간에 반복하지 않는다.
- 클로바더빙 이용약관과 무료 플랜 범위를 지킨다.
  - 자동화 도구 사용이 약관상 허용되는지는 시작 전에 사용자에게 확인을 요청한다.
  - 무료 사용량(글자 수, 다운로드 횟수)을 넘길 것 같으면 먼저 알린다.
- **출처 표기**: 앱의 '만든 사람들' 화면과 `docs/ASSETS.md`에 "음성: 네이버 클로바더빙"을 표기한다.
- 이 작업이 끝나면 HANDOFF.md에 다음을 기록한다.
  - 사용한 프로젝트 이름
  - 옵션 값
  - 다운로드에 쓴 횟수
  - 남은 작업

## 14. Git 규칙 (GitHub: JEONJOOHYUN/nyamnyam-canvas)

- **원격 저장소**: `origin` = https://github.com/JEONJOOHYUN/nyamnyam-canvas.git

```
  /app, /components, /lib, /content, /public   ← Next.js 웹앱
  /supabase                                      ← 마이그레이션, Edge Function
  /firmware/nyamnyam                             ← ESP32 Arduino 코드
  /scripts                                       ← 음성 자르기 등 도구
  /docs                                          ← FIRMWARE_NOTES, ASSETS, VOICE_SCRIPT
  HANDOFF.md, README.md
```

- **브랜치는 두 개만 쓴다.**
  - `dev`: 평소 작업 브랜치. Vercel이 미리보기(Preview) 주소로 배포한다.
  - `main`: 발표나 시연에 쓰는 안정 버전. Vercel이 실제(Production) 주소로 배포한다.
  - 11장의 각 단계가 끝나고 테스트가 통과하면 `dev`를 `main`에 합친다. 합치기 전에 나에게 확인받는다.
- **커밋**
  - 작은 단위로 자주 한다. 메시지는 한국어로 쓰되 앞에 종류를 붙인다.
  - 종류: `feat:` 기능, `fix:` 버그, `docs:` 문서, `refactor:` 구조 개선, `test:` 테스트, `chore:` 설정, `firmware:` ESP32 코드
  - 예: `feat: 시뮬레이터 무게 소스와 식사 상태 머신 추가`
  - 하루 작업을 마치거나 세션을 끝낼 때는 HANDOFF.md를 갱신하고 커밋한 뒤 `dev`에 push한다. 다른 컴퓨터에서도 이어서 할 수 있게 하기 위해서다.
- **push 전 확인**
  - `lint`, `typecheck`, `test`가 통과해야 한다.
  - 비밀값이 들어간 파일(`.env*`, `secrets.h`, 원본 음성 대용량 파일)이 포함되지 않았는지 확인한다.
- **force push와 히스토리 삭제는 절대 하지 않는다.** 필요하면 먼저 나에게 물어본다.
